> 这是 Go 九个任务的结业考核。你要做一个**有用户、有权限、有配额、能对外开放接口**的短链接服务——一个麻雀虽小、五脏俱全的真实后端。

## 一、你要做的东西

一个短链接服务,但它是**有"用户"的**:每个人注册登录后管理自己的短链,有每日创建上限,还能拿 API Key 给别的程序调用。

完整使用流程长这样:

```
# 1. 注册
$ curl -X POST .../register -d '{"username":"tom","password":"123456"}'
{"message":"注册成功"}

# 2. 登录,拿到 token
$ curl -X POST .../login -d '{"username":"tom","password":"123456"}'
{"token":"eyJhbGci..."}

# 3. 带 token 创建短链(没 token 会被拒绝)
$ curl -X POST .../shorten -H "Authorization: Bearer eyJhbGci..." \
       -d '{"url":"https://go.dev"}'
{"code":"a1B2c3","short_url":".../a1B2c3"}

# 4. 访问短链 → 302 跳转 + 点击计数
$ curl -i .../a1B2c3   →   HTTP/1.1 302 Found ...

# 5. 当天创建超过配额后,被拒绝
$ curl -X POST .../shorten -H "Authorization: Bearer ..." -d '{"url":"..."}'
{"error":"今日创建次数已达上限"}
```

## 二、必做功能

**用户与鉴权**

- [ ] 注册、登录两个接口
- [ ] **密码必须哈希后存储**(绝不能明文!用 bcrypt 之类)
- [ ] 登录成功返回一个 token,之后创建 / 管理短链都要带这个 token
- [ ] 没带或带错 token,返回 401

**短链核心**
- [ ] 创建短链(需登录)
- [ ] `GET /:code` 做 302 跳转,并给点击数 +1
- [ ] 列出 / 查看短链 —— **每个用户只能看到和管理自己的**(数据隔离)

**配额限制**
- [ ] 每个用户**每天最多创建 N 条**短链(N 来自配置文件),超出返回明确错误

**工程底线**
- [ ] 端口、数据库、每日配额 N 等走配置,不写死
- [ ] 至少 1 个 `go test`
- [ ] 该处理的错误都处理,程序不能崩

## 三、选做功能(加分,越像真实 SaaS 越高分)

- **API Key / 对外开放接口**:给用户生成一个 API Key;第三方程序带着这个 key(而不是登录 token)就能调用"创建短链"接口。这就是"对外放 API"的标准做法。
- **更细的限流**:除了每日配额,再加"每分钟最多 X 次请求"(用中间件实现)。
- **统计接口**:返回"我的短链总点击数""我最热门的短链"。
- 短链**过期失效** / **自定义短码** / 同一长链接**查重复用**。
- 把**鉴权和限流写成中间件**(体现你会组织代码,而不是每个接口里复制粘贴)。
- 用 **Docker** 打包项目。
- 换用非教程技术栈(echo / fiber / 标准库 / MySQL 等)并能说清取舍。

## 四、教程没教、需要你和 AI 一起学的部分

直说:**下面这些九个任务没讲过**,需要你自己查资料、问 AI 去学会。这不是为难你——**"快速学会没学过的东西"正是这次考核的核心。** 给你指个路:

| 你要解决的问题 | 关键词 / 工具 |
|---|---|
| 密码怎么安全存储 | 哈希,`golang.org/x/crypto/bcrypt` |
| 登录后怎么"记住"用户 | JWT(`github.com/golang-jwt/jwt`),或随机 token 存库 |
| 怎么让某些接口"必须登录才能用" | 中间件(middleware) |
| 怎么限制访问频率 | 计数 + 时间窗口,或 `golang.org/x/time/rate` |

学的时候记住第〇节那句话:**让 AI 教你、帮你写,但每一行你都要能解释为什么。**

## 七、评分标准

| 维度 | 占比 | 看什么 |
|---|---|---|
| 功能完整 + 能跑 | 40% | 注册登录、鉴权、短链、数据隔离、每日配额是否都正确实现 |
| AI 协作说明 | 30% | 逐行讲解(尤其鉴权/配额段)、报错处理、安全自查是否到位 |
| 安全 & 工程规范 | 15% | 密码哈希、配置不写死、分层 / 中间件组织 |
| 选做 / 挑战 | 15% | API Key、限流、统计、换技术栈等 |

> **硬性扣分项(红线):**
> - 密码**明文存储** → 重大扣分
> - token / API Key / 密码等**写死在代码里或提交进 git** → 重大扣分
>
> 这两条是安全底线。如果是 AI 写的、你没发现也照样扣——因为**审出 AI 的安全漏洞,正是你要会的能力**。
